# Arc

Личная практика по OpenSpec: один трек, пять заданий и сохранённый разбор. Интерфейс на русском, приложение доступно только на локальном компьютере.

## Запуск

Нужны Node.js 22.12+ и запущенный Docker Desktop.

```sh
npm ci
cp .env.example .env
docker compose up -d --wait
npm run db:migrate
npm run dev
```

Откройте http://127.0.0.1:5173. Сервер работает на 127.0.0.1:3001, PostgreSQL — 127.0.0.1:54329. Для запуска собранного приложения:

```sh
npm run build
npm start
```

Тогда открывайте http://127.0.0.1:3001. Черновики привязаны к origin браузера: при смене порта неотправленный черновик автоматически не переносится. Принятые ответы хранятся в PostgreSQL.

## OpenAI API — можно подключить позднее

Без ключа доступны трек, задания с выбором ответа, история и интерфейс открытого ответа. Открытый ответ сохраняется, но его проверка сообщает, что API не настроен. Техническая ошибка не становится оценкой «неверно».

Когда отдельный API-биллинг настроен, добавьте в локальный `.env`:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-5.4-mini-2026-03-17
OPENAI_INPUT_PRICE=0.75
OPENAI_OUTPUT_PRICE=4.50
OPENAI_PRICING_CONFIRMED=true
```

Числа — тарифы, проверенные при планировании; перед включением сверьте их с [официальной карточкой модели](https://developers.openai.com/api/docs/models/gpt-5.4-mini) и доступностью модели в вашем аккаунте. `.env` исключён из Git. Не добавляйте ключ в `VITE_*` и не отправляйте его в чат. После изменения окружения перезапустите сервер и нажмите «Повторить проверку» для сохранённого ответа.

Приложение резервирует максимальную стоимость запроса, учитывает фактический usage и останавливает новые платные запросы при общем лимите $5. Тренировки и eval используют один бюджет. При неопределённом результате запроса резерв консервативно считается потраченным. Миграция и перезапуск не сбрасывают бюджет. Внешние расходы с тем же ключом и будущие изменения тарифа этим локальным счётчиком не контролируются. Расходы видны на странице трека в «Материалы и расходы API».

## Стиль кода

Единый формат задаёт Prettier: отступ — 2 пробела, одинарные кавычки в TypeScript,
точки с запятой, завершающие запятые и переносы строк LF. Ориентир длины строки —
100 символов; длинные строки с текстом форматтер может оставить целиком.
Правила хранятся в `.prettierrc.json`, базовые настройки редакторов — в `.editorconfig`.

```sh
npm run format        # отформатировать проект
npm run format:check  # проверить без изменения файлов
```

В VS Code установите рекомендованное расширение Prettier: настройки проекта включают
форматирование при сохранении. Для другого редактора подключите Prettier и EditorConfig.
Используйте локальную версию Prettier из зависимостей проекта, чтобы результат совпадал с CI.
GitHub Actions проверяет форматирование при push и в pull request.
Сборки, зависимости, отчёты и установленные инструкции агентов исключены из форматирования.

## Проверки

```sh
npm run format:check
npm test
npm run build
npm run eval -- --dry-run
```

Для браузерных проверок (тоже без OpenAI API):

```sh
npx playwright install chromium
npm run build
npm run test:browser
```

Playwright запускает отдельный сервер на порту 3002 с тестовым оценщиком и отдельной схемой PostgreSQL, проверяет весь сценарий и мобильную вёрстку. Скриншоты находятся в `test-results/`.

`npm test` требует PostgreSQL, создаёт отдельную случайную схему `arc_test_*` и удаляет только её по завершении. Тестовый оценщик не вызывает API и не доказывает качество AI.

После настройки ключа:

```sh
npm run eval
```

Команда запускает 18 размеченных ответов и 3 проверки обхода рубрики дважды. При указанных тарифах верхняя оценка резерва — $0.6615 за 42 запроса. Отчёт с конфигурацией, ответами, оценками, метриками и расходами сохраняется в `reports/evaluations/`. Он содержит тестовые учебные ответы, но не ключ. Прерывание процесса оставляет резерв до восстановления по deadline; не удаляйте его вручную ради нового запуска.

Приёмка: в каждом прогоне 100% валидной структуры, ≥90% совпадений критериев и категорий, успешные проверки обхода рубрики; затем вручную сверить объяснения с источниками и разобрать каждое расхождение. Не должно остаться существенных ошибок. Отчёт намеренно имеет `accepted: false` и `manualReview: pending` до отдельного ревью. Смена модели/промпта/рубрик требует нового полного прогона. До реального прогона AI-качество не принято.

## Данные и восстановление

`docker compose stop` останавливает базу, сохраняя volume. `docker compose up -d --wait` запускает её снова. Не используйте `docker compose down -v`, если нужно сохранить историю. Повторный `npm run db:migrate` безопасен для существующих сессий и бюджета.

Сессия продолжится после перезапуска. Неотправленный черновик хранится в этом браузере; очистка данных сайта удалит его. Принятый ответ неизменяем; после технической ошибки повторно оценивается тот же текст. Если сервер прервался во время проверки, дождитесь до 90 секунд и повторите проверку. Поздний результат старой попытки не перезаписывает новую оценку.

Перед изменениями базы сохраните резервную копию, например в игнорируемую папку `backups/`, через `docker compose exec -T db pg_dump -U arc -d arc`. Вывод этой команды необходимо перенаправить в файл. Обычный откат — остановка приложения и возврат прежней сборки с сохранением volume.

## Источники и границы

См. `docs/learning-sources.md` и `openspec/changes/practice-openspec-track/`. Тренировка проверяет только три учебные области; остальные навыки отмечаются «Не проверялось». После личной тренировки полезно записать, какие объяснения помогли, какие оценки спорны и какие пробелы обнаружены. Это обратная связь для следующей итерации, не доказательство улучшения знаний.
